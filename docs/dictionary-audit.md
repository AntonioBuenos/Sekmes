## Обнаруженная аномалия данных

В уроке 20 литовское поле для «смотреть телевизор» содержит кириллицу:
`žiūrėti телевизориў`. Аудит фиксирует проблему, но не исправляет учебный
материал в рамках этого шага. При миграции запись сохраняется как отдельная
статья; исправление текста должно быть явным редакторским решением и не должно
менять назначенный `wordId`.

## Правила стабильных идентификаторов

1. Формат существующих записей при миграции: `word_000001`, `word_000002` и
   далее. ID назначаются один раз по порядку первого появления в текущих уроках
   и после сохранения в JSON никогда не пересчитываются.
2. ID является непрозрачным ключом. Он не строится из `lt`, `ru`, типа, номера
   урока, позиции в списке или нормализованной формы.
3. Полностью одинаковые `lt + ru + type` объединяются и получают один ID.
4. Разные значения, разные типы или отличающиеся полные учебные записи получают
   разные ID, даже если их начальная литовская форма совпадает.
5. Новое слово получает следующий свободный номер. Удалённые номера повторно не
   используются.
6. Редакторская правка текста не меняет ID. Если статьи позднее объединяются,
   старые ID сохраняются как aliases к каноническому ID; при разделении
   создаётся новый ID для новой статьи.
7. Урок хранит упорядоченный список `wordId`; одинаковый `wordId` может
   использоваться в любом количестве уроков и курсов.
8. Основной индекс приложения — `Map<WordId, DictionaryEntry>`. Вторичные
   нормализованные индексы служат поиску, но не определяют идентичность статьи.

## Воспроизведение

Из корня проекта:

```powershell
node .\tools\audit-dictionary.mjs
```

Скрипт печатает JSON со статистикой текущего каталога, количеством ссылок уроков,
дубликатами ID и отсутствующими ссылками. Детальный результат первоначального
аудита сохранён в этом документе.
